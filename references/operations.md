# Операционка: как гонять батчи и обходить лимиты инструментов

Практика, набитая на реальном прогоне ивента 260722 (336 регистрантов). Экономит часы и токены.

## Батчи параллельными агентами
- **Агенты пишут результат в JSON-файлы, а не в ответ.** Ответ агента возвращается в контекст оркестратора и раздувает его. Правильно: агент делает работу → пишет `res_XX.json` → возвращает одну строку-резюме. Оркестратор потом читает файлы скриптом.
- **Не запускай больше ~8–10 агентов разом.** При 14 одновременных часть падает на старте (0 вызовов инструментов, мусорный ответ). Лучше **волнами по 6**.
- **Всегда проверяй, какие res-файлы реально появились**, и перезапускай недостающие чанки — тихие падения на старте это норма, а не исключение.
- **Размер чанка:** WebFetch-задачи ~15–18 доменов на агента; Pipedrive-задачи ~10–12 оргов (там больше вызовов на единицу).
- **Дедуп по компании перед батчем** — считать трафик/кейс на орг, а не на каждого регистранта (у нас 336 персон = 305 орг).
- **Оркестратор пишет в Sheet сам**, централизованно, после сверки — так проще откатывать и не ловить гонки. Если пишут агенты — только в СВОИ строки/столбцы.

## Pipedrive MCP — лимиты и приёмы
- **`getDeals` без `custom_fields` рвёт лимит** (блоб из 60+ полей, ~4КБ на сделку). Всегда передавай `custom_fields="<любой валидный ключ>"` — ответ схлопывается до строки на сделку.
- **`include_fields` — скаляр, не CSV** и не массив: `"activities_count"` ок, `"a,b"` → ошибка. Одно доп-поле на вызов. Валидные: `activities_count`, `done_activities_count`, `first_won_time`, `notes_count` и т.п. (`won_time`/`close_time` туда НЕ входят — они и так в теле сделки).
- **`getStages(limit:500)` — ОДИН вызов на прогон**, ответ уходит в файл и парсится скриптом. ⚠️ Совет «точечный `getStage(id)` на каждую сделку» ОТМЕНЁН 21.07.2026: именно он давал 143 лишних вызова в прогоне 17.07. 265 стадий в файле дешевле сотни точечных запросов.
- **`getUsers`/`getUser` в этом MCP НЕТ.** Имя владельца — через `getNotes(user_id=<owner>, limit=1)` → `data[0].user.name`. Кэшируй id→имя, овнеры повторяются.
- **`getOrganizations(ids=…)`** — до 100 id за вызов, с `custom_fields` + `include_option_labels=true` (иначе придут id опций, а не подписи).
- **Большие ответы (getPersons по фильтру на 300+)** уходят в tool-result файлы — парсить скриптом, в контекст не тянуть.

## Google Sheets API — грабли
- **Запись в ОБЪЕДИНЁННЫЙ диапазон заполняет только верхнюю-левую ячейку.** Если пишешь строку в область, где стоит merge (напр. A9:C9), сначала **разъедини**, потом пиши — иначе значения B/C молча теряются.
- Два разных метода: `values().batchUpdate` (значения) и `spreadsheets().batchUpdate` (структура/формат). Не путать.
- Цвета возвращаются с плавающей точностью — сравнивать с допуском (~0.02), иначе форматтер будет «переписывать» одно и то же.
- Колонки искать **по имени заголовка**, не по индексу — порядок может поехать.

## Внешние источники: что реально работает
- **SimilarWeb (трафик):** ⚠️ **НЕ используем с 21.07.2026** — фаза Traffic удалена, посещаемость берётся из поля Pipedrive as-is. Историческая справка, почему отказались: число визитов рисуется в SVG-графике (WebFetch его не видит → ложный «нет данных»), free-тариф даёт ≈3 проверки на сессию/IP, дальше CloudFront 403 под видом пустой страницы; агент на 30 доменах работал 20+ минут и ловил сталлы. Массово трафик так не собрать.
  - 🚫 **Скриптом (requests/curl) SimilarWeb не берётся** — проверено 19.07: и `data.similarweb.com/api/v1/data`, и обычный HTML отдают **CloudFront 403** на серверные запросы. Единственные рабочие пути — WebFetch/браузер. Значит масштаб решается не «более быстрым сбором», а **меньшим количеством доменов**.
  - ✅ **Главное:** поле «Посещаемость» в Pipedrive = **`5955678b…`** (заполнено у 170 из 293 орг). Читать его в общем bulk-проходе. Замер 19.07: это снимает **62% походов в SimilarWeb**.
- **Журнал Mindbox (кейсы):** каталог на вид JS, НО **ленты тегов server-side rendered** — читаются через `fetch` внутри страницы, без кликанья. Индекс тегов: `/journal/tag/`. Так за один проход снимается ~30 тегов / 400+ кейсов.
- **Каталог партнёров Mindbox:** наоборот, чистый Vue — имён нет в HTML, нет API. Только браузер + клик по карточкам («Кейсы и контакты» → `.partner-popup__title`).
- **Notion (MDR Playbook):** WebFetch не может (редиректы/авторизация) → читать **через браузер** с залогиненным профилем по инвайт-ссылке. Коннектор Notion требует OAuth, в неинтерактивной сессии не поднять.
- **Сайты лидов:** часть отдаёт JS-скелет (SPA) или блокирует автозапросы — это **не** признак мусорного домена (см. `edge_cases.md`).

## Гигиена данных таблицы
- **Фикс-поля писать значениями из списка**, а не свободным текстом. Реальный косяк: столбец «Бизнес-модель» местами заполнен описаниями вроде «неясно (домен molnio.ru)», «Личный бренд/инфобизнес» — это ломает фильтрацию и аналитику. Только значения из списка в `qualification_criteria.md`; не подходит ничего → ближайшее по смыслу.
- Домены нормализовать при записи (без `http(s)://`, `www.`, `/`, `#`), строчными.
